# 금융 의사결정 데이터셋 카드 — 초안 0.1

사용자가 좁힌 최신 범위의 타입 분리 입력, 공통 위험, 다중 계획·질문·유보, 한 조건 변경 쌍은 [V3 데이터·모델 구현 기록](../../research/FINANCIAL_CORE_V3.md)과 [`episode_v3.schema.json`](../../contracts/episode_v3.schema.json)에 있다. V3는 2,000건의 합성 사례를 검증했지만, 실제 API 사례는 권한·출금 조건·원천 시각을 확인하지 못해 학습 제외 초안으로 유지한다.

2026-09-24 [TRON 실관측 릴리스](../../research/REAL_TRON_DATA_20260924.md)를 추가했다. USDD 일별 366건과 JustLend 계약 이벤트 800건을 원문과 대조했고, FDC 시계열 부분만 자기지도 방식으로 학습했다. 실제 배분 정답은 0건이며 첫 예측 실험은 단순 기준선보다 나빴다. 실관측 자료의 재배포·학습 권한은 아직 `unknown`이다.

[소비자용 데이터·지속 학습 계약](../../research/CONSUMER_GRADE_DATA_LEARNING_20260924.md)에 주기 수집과 새 일자만 학습하는 연구 후보 루프를 기록했다. USDD TRON 볼트별 담보 비율·부채·한도를 추가 수집하지만 아직 계획 정답이나 제품 추천에는 사용하지 않는다. 사람이 검토한 실제 배분 정답은 계속 0건이다.

[배분 판단 오라클](../../research/ALLOCATION_ORACLE_20260924.md)은 V3의 합성 계획에서 7,935개 제약 통과·위반 사례를 채굴했다. 이는 `synthetic_constraint_only`이며 실제 배분 정답 수를 늘리지 않는다. 실제 TRON 사례는 원문 대조가 가능해도 출금·비용·권한 근거가 부족하면 `excluded_unreviewed`로 남는다.

[자율 데이터 생산 엔진](../../research/AUTONOMOUS_DATA_ENGINE_20260924.md)은 Cherry에서 매시간 새 공식 수집본과 역사 릴리스를 검증해 사실·변화 사례를 만든다. 2026-09-24 기준 2,056건 중 실제 배분 정답은 0건이다. 반복 수집값은 중복 사례로 세지 않고 원천 수정은 별도 기록한다. 원천 재사용·학습 권한 `unknown` 때문에 사례를 모델 학습으로 자동 투입하지 않는다.

[형식 최적 배분 정답 엔진](../../research/FORMAL_OPTIMAL_LABELS_20260924.md)은 실제 시장 상태 14개와 자동 생성한 사용자 조건을 결합해 정해진 총수익률 대리 목적함수의 전역 최적해 1,512건 및 조건 변경 쌍 3,528건을 계속 만든다. 이 수학적 정답은 실행 가능한 소비자 최적 배분 정답이나 권한 확인된 학습 골드와 구별한다. 원천 권한과 출금·비용 근거가 없어 `real_customer_optimum=false`, `training_scope=excluded_rights_unknown`이다.

실관측 JSONL의 별도 계약은 [`tron_observation_v1.schema.json`](../../contracts/tron_observation_v1.schema.json)이다. 관측 행은 원천 원문·상품 주소·단위·사건 시각·실제 수집 완료 시각을 분리하고, 배분 라벨을 `null`로 고정한다.

## 실제 포함한 것

- `contracts/decision_case.schema.json`: 작은 판단 사례의 형식과 태스크별 허용 정답.
- `contracts/model_binding.template.json`: Qwen 32B 요구와 아직 미확인인 endpoint/모델 ID 구분.
- `cases/seed_decisions.jsonl`: 합성 개발 초안 16건, 4개 태스크에 각각 4건.
- `contracts/episode_v2.schema.json`: 금융 상태·배분·근거의 학습/평가 에피소드 계약.
- `research/fdc/synthetic.py`와 `validate.py`: 명시적 합성 사례 생성기와 예산·출처·분할·권한 게이트. Cherry에서 2,000건을 생성·검증했다.
- `src/finagent/episode.py`: 공식 API 스냅샷이 수집된 뒤에만 작동하는 사례 초안 작성기. 산출물은 `excluded/unreviewed/rights_unknown`이다.
- `src/finagent/history.py`: 실제 수집 완료 시각을 기준으로 원문 해시·정규화 값을 대조하는 시간순 관측 내보내기. 검토 전 연구용이며 정답 라벨이 아니다. 초기 요청 시작 시각으로 기록된 수집본은 시점 평가에서 제외한다.

모든 seed는 `synthetic`, `development`, `draft_unreviewed`, `author_proposal`이다. Codex가 작성한 합성 사례와 제안 라벨이며 독립적인 사람 검토가 끝난 골드가 아니다. 실제 금융상품의 금리·약관·체결 자료가 아니다. 합성 금리를 화면/검색/추천의 실제 값으로 사용해서는 안 된다.

## 데이터 분리

`DecisionCase`는 라벨을 포함하는 보관 형식이다. 모델에는 `task_id`, `state`, `question`, 태스크별 허용 답만 전달한다. `label`, 검토 근거, split 이름이나 정답 파일 경로는 전달하지 않는다. 모델 응답은 별도 예측 파일에 보존하며 원래 라벨을 덮어쓰지 않는다.

실제 관측은 별도의 FactStore에 보존한다. 사례의 `source_ref`와 `locator`가 당시 원문에 연결되어야 한다. 이번 합성 자료의 `fixture:` 참조는 이 파일 내 작성한 자료를 식별할 뿐 외부 원천을 가리키지 않는다. `observed_at: null`은 라이브로 관측하지 않았다는 뜻이다. `as_of`는 사례 맥락의 시간이며 실제 수집 시간의 증거가 아니다.

## 태스크별 라벨링 규칙

| 태스크 | 판단 규칙 | 유보 |
|---|---|---|
| intent.route | 현재 발화와 명시된 대화 상태로 사용자가 요청한 기능을 구분 | 지시 대상이 없거나 조회/행동이 모호하면 UNCLEAR |
| meaning.metric | 주체·연율 방식·보상 포함 여부가 근거에 명시된 경우만 분류 | 단순히 `yield=8`처럼 정의/단위가 없으면 UNKNOWN |
| evidence.relevance | 질문에 직접 답하는 문단 DIRECT, 배경만 주는 문단 CONTEXT, 무관 IRRELEVANT | 필요한 문단·대상이 비어 있거나 판정 불가능하면 INSUFFICIENT |
| evidence.support | 제시한 **주장 전체**를 근거가 지지하면 SUPPORTED, 명시적으로 반대면 CONTRADICTED | 침묵·예시·추정·명령문만으로 실제 사실을 확인할 수 없으면 INSUFFICIENT |

`BASE_APR`은 단리 방식의 기본 공급 금리, `TOTAL_APY`는 보상 포함 여부와 복리 가정이 명시된 총 연수익률, `REWARD_RATE`는 별도 인센티브 성분, `BORROW_RATE`는 차입자가 내는 금리다. 정의가 충분하지 않으면 수치가 있어도 UNKNOWN이다. 분류와 숫자 변환·계산은 별개 작업이다.

`SUPPORTED`는 **이 사례에 제공된 문장이 해당 주장을 지지한다**는 의미다. 원문 자체의 사실성, 최신성, 실행 권한을 보장하지 않는다. 별도 원천/시점/실행 검증이 필요하다. `DIRECT` 역시 사실 검증이나 실행 허용 상태가 아니다.

## 자동 검증과 선택적 사람 검토

사용자나 소유자가 모든 사례를 검토하는 운영 방식은 채택하지 않는다. [검토 부담을 줄이는 운영 계약](../../research/REVIEW_ROUTING_20260924.md)에 따라 원문 수집·권한·단위·시점 확인과 예산·위험·출금 제약 계산은 기계가 수행하고, 판정 근거를 해시·원문 위치·규칙 버전으로 남긴다. 기계가 증명한 **제약 판정**은 그 좁은 범위의 라벨로만 사용한다. `CONSTRAINTS_PASS`를 최적 배분이나 구매 적합성 정답으로 승격하지 않는다.

자료 누락은 수집·사용자 조건 질문 대기열로, 원문 충돌·규칙 미정의·오라클 불일치·실제 배분의 주관적 우열은 독립 검토 대기열로 보낸다. 별도로 무작위 표본과 위험도가 높은 경계 사례를 독립 감사해 자동 판정 오류를 측정한다. 정확도나 오류율이 확인되기 전에는 임의의 자동 승인율을 목표로 삼지 않는다. 사용자는 자신의 조건을 정정하고 실제 구매를 승인할 때만 관여하며, 데이터 라벨러 역할을 맡지 않는다.

사람이 `adjudicated` 정답을 만들 때에는 모델 예상 답을 먼저 보지 않고 원문·사용자 조건·근거 ID를 확인한다. 현행 V2 스키마의 `adjudicated`는 서로 다른 reviewer ID 두 개 이상을 요구한다. 이는 **사람 판정 정답의 형식**에만 적용되며 모든 자동 제약 판정의 필수 조건이 아니다. ID 개수만으로 독립 검토가 입증되지는 않는다. 불일치·자료 부족·검토 시각·권한과 라벨 수정 이력을 별도로 기록하고 기존 평가 원문을 덮어쓰지 않는다.

## 조건 변경 사례

`family_id`가 같은 사례는 같은 split에 둔다. 예를 들어 seed 13/14는 동일 근거에 대해 주장 하나를 바꾼다. 이후에는 예산·수수료·기한·허용 상품·즉시 출금 요구·현재 체인·견적 유효 여부를 한 번에 하나씩 바꾼 가족을 만든다.

지출/승인/거래 상태 사례는 향후 별도 action schema로 확장한다. 현재 네 가지 의미 판단 라벨을 실행 허가로 사용하는 것은 금지한다. 정확한 금액 계산이나 승인 여부를 Qwen이 분류하게 해 정답을 대체하지 않는다.

## 품질·누출 검사

Cherry에서 JSONL 스키마·예산·출처·가족 분할·권한 게이트를 실행했다. 아래 나머지 검사는 계속 확대해야 한다.

- JSONL 파싱과 Draft 2020-12 검사. `format` 검사를 명시적으로 활성화한다.
- case ID 중복, episode/family split 충돌, 동일 문단·패러프레이즈의 평가 유출 검사.
- label의 evidence ID가 해당 state에 존재하는지 검사.
- 원문 위치·시점·해시·권한이 실제 소스에 연결되는지 검사. 합성은 실원천으로 승격하지 않는다.
- sealed/calibration에 미검토 자료나 학습용 가족이 들어가지 않았는지 검사.
- 모델 입력에 정답/검토 근거가 포함되지 않았는지 검사.
- 금액은 원시 정수/Decimal 문자열로, 0/결측/오류는 구별. 현재 의미 판단 schema에는 실행 금액 필드를 넣지 않았다.

## 평가와 확대 목표

최소 120 / 목표 300개는 **평가에 사용할 독립 에피소드 수**이며 사람이 모두 읽어야 할 건수가 아니다. 증명 가능한 제약 라벨은 자동 검증하고, 주관적 배분 판단과 독립 감사 표본만 사람 검토 대상으로 센다. 여러 atomic case가 파생되어도 독립 시나리오 수를 부풀리지 않는다. 목표 300 에피소드의 150 개발 / 50 보정 / 100 봉인 배정은 family 기준으로 수행한다. 정확한 유형별 실제 수량과 사람 검토량은 확보 이후 릴리스 매니페스트로 보고한다.

단순 정답률 외에 유보율과 답할 수 있는 문제의 완결 응답률을 함께 측정한다. 오분류 비용이 다른 태스크는 평균 하나로 합치지 않는다. 확신도는 현재 저장하지 않는다. 미래 확률 모델은 별도 보정셋과 calibration 버전을 요구한다.

## 상태와 한계

2026-09-24 Cherry 서버에서 공식 API 여섯 원천을 읽기 수집하고 합성 에피소드 2,000건을 검증·학습했다. 실제 API 사례 초안 한 건은 분할 `excluded`, 검토 `unreviewed`, 권한 `unknown`으로 검증했다. 사람이 검토한 골드, Qwen 호출, 확률 보정, 독립 금융 평가, 브라우저 확인 화면, 테스트넷 거래는 없다. Mac에서는 파일 편집과 읽기만 수행했다.
