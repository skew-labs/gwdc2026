# 서버가 계속 생성하는 배분 최적해 정답 — 증명 범위와 운영 상태

2026-09-24 Cherry `charmed-weasel`에 구현·가동했다. 수집기(`gwdc-finance-collector.service`)가 공식 원천을 10분 간격으로 저장하고, 활성화된 `gwdc-finance-auto-cases.timer`가 매시간 [`autonomous_pipeline.py`](fdc/autonomous_pipeline.py)를 시작한다. 서버 재시작 뒤에도 타이머가 예약 작업을 이어간다. 파이프라인은 원문 사실·변화 사례에 더해 [`formal_optima.py`](fdc/formal_optima.py)로 **최적 배분 정답과 조건 변경 쌍**을 새 시장 상태마다 자동 생성한다. 사용자나 소유자의 건별 라벨링은 필요 없다.

## ‘최적’의 정확한 정의

동일 토큰(USDT 또는 USDD) 내에서 보유액을 남기고 JustLend V1 활성 공급 시장에 배분한다. 각 시나리오는 실제 API 수집 시점의 공급 기본 연율 `rᵢ`와 시장 현금 `Cᵢ`를 원문에 대조하고, 합성 사용자 조건인 예산 `B`, 즉시 보유액 `R`, 총 위험 비율 `α`, 공통 위험 비율 `β`, 기간 `H`를 사용한다. 모든 금액은 해당 토큰의 최소 단위 정수로 바꾼다.

> 최대화: `Σ(배분량ᵢ × 관측 기본 연율ᵢ × H/365)`  
> 제약: `배분량ᵢ ≥ 0`, `배분량ᵢ ≤ 관측 시장 현금ᵢ`, `Σ배분량ᵢ ≤ B−R`, `Σ배분량ᵢ ≤ αB`, `Σ배분량ᵢ ≤ βB`.

점수는 **단리 형태의 비교용 총수익률 대리값**이다. 실현 수익이나 순수익 계산이 아니다. 공식 [JustLend API 설명](https://docs.justlend.org/developers/apis/)의 `supplyRate`는 연율화된 기본 공급 수익률이며 채굴 보상과 별개다. 시장 `cash`는 이 연구 시나리오의 보수적인 배분 상한 대리값일 뿐 실제 예치 한도나 미래 출금 보장이 아니다. 수수료, 보상 변동, 가격·페그 위험, 잠금·출금 약관과 거래 경로는 목적함수에 포함되지 않았다. 따라서 산출물의 `FORMAL_OPTIMUM`은 **명시된 문제의 정확한 정답**이지만 실제 고객의 최선 투자나 구매 허가가 아니다.

금리가 높은 시장부터 토큰 원자 단위로 상한까지 채워 최적해를 만든다. 별도의 `verify()`는 예산·보유액·시장 현금·위험 상한을 다시 계산하고, 더 높은 금리의 시장에 여유가 있는데 낮은 금리 시장에 배분한 경우를 거부한다. 이 교환 논증과 정확한 유리수 점수 일치로 전역 최적성을 확인한다. 같은 금리에는 상품 ID로 결정적 순서를 준다. 원문 상품 주소·기초 토큰·자릿수·금리·현금이 동일 JSON 행에 있는지도 재확인한다.

## 자동 생성과 품질

실제 시장 상태 1개당 예산 3종, 즉시 보유 비율 3종, 총 위험 상한 3종, 공통 위험 상한 2종, 기간 2종을 조합한다. 각 시나리오에서 `input`과 최적 배분 `target`을 분리하고, 한 조건만 바뀐 `COUNTERFACTUAL_PAIR`를 연결한다. 조건을 바꿔도 최적 배분이 같으면 그대로 기록한다. 입력에 정답을 끼워 넣지 않는다. 동일한 경제적 시장 상태의 반복 수집은 새 정답으로 세지 않는다.

2026-09-24 Cherry 검증 시 원천 시장 스냅샷 9개에 걸친 **서로 다른 자산·시장 상태 14개**에서 `FORMAL_OPTIMUM` 정답 1,512건과 조건 변경 쌍 3,528건을 생성했다. 1,512개가 독립적인 실전 시장 상태 1,512개라는 뜻은 아니다. [`validate_formal_optima.py`](fdc/validate_formal_optima.py)가 저장 배치의 해시·공식 원문·상품 식별·최적해 증명·한 조건 변경 여부를 다시 검사해 9/1,512/3,528건 모두 통과했다. Cherry 전체 테스트 38건도 통과했다. 같은 입력 재실행의 새 정답은 0건이었다.

결과는 `data/auto-cases/formal/batches/`의 불변 JSONL, `formal.sqlite3` 색인, `latest.json`에 저장한다. 전체 파이프라인의 마지막 성공과 마지막 시도는 `data/auto-cases/pipeline_latest.json`, `pipeline_latest_attempt.json`으로 구분한다. 원문 손상, 상품 식별 불일치, 단위 변경, 해시 변조, 새로운 미지원 조건이 있으면 새 정답 생성을 중단하고 실패를 기록한다. 다른 프로젝트의 Cherry 서비스·경로는 수정하지 않았다.

## 실제 금융 판단으로 넓히는 조건

현재 정답의 원천 사실은 실관측이지만 사용자 조건은 자동 생성한 연구 템플릿이다. `rights_status=unknown`, `training_scope=excluded_rights_unknown`, `real_customer_optimum=false`, `product_actionable=false`를 모든 정답에 붙인다. 원천 학습 권한이 확인되기 전에는 모델 학습 입력으로 자동 승격하지 않는다. 미래 출금 조건·확정 비용·실제 체결/출금 결과가 확보되면 목적함수와 제약을 버전 올려 넓히고 새 최적해를 다시 증명한다. **현재의 1,512건은 제약과 목적함수가 명시된 수학적 최적 정답**이며, 미확인 조건을 숨긴 소비자 추천 정답으로 재표기하지 않는다.
