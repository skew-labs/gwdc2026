# 소비자용 금융 에이전트 데이터·지속 학습 계약

2026-09-24. 목표는 대회 시연을 넘어서, 일반 사용자가 금액·시점·출금 조건을 말하면 **근거 있는 여러 계획 또는 명확한 유보**를 받는 제품이다. "블룸버그가 일반인에게 내놓은 금융 에이전트"는 데이터 신뢰도와 설명 수준의 목표이지 현재 제품 성능에 대한 주장이나 제휴 표시가 아니다. 이번 구현 범위는 데이터셋과 금융 판단 구조이며 지갑 실행은 포함하지 않는다.

## 지금 작동하는 데이터 루프

1. Cherry의 격리 경로에서 10분마다 JustLend/USDD 공식 읽기 API 6개를 수집한다. 응답 원문·SHA-256·수집 **완료** 시각·JSON 위치·상품 주소·단위·0/결측/해당없음을 분리해 보존한다. 2026-09-24 현재 JustLend 시장 24개(활성 18, 레거시 6)에서 시장당 10개 지표, USDD TRON 볼트 9개에서 볼트당 10개 지표 및 프로토콜 지표 4개를 실제 응답에서 정규화했다. `PASS_FOR_RESEARCH_READ`는 원문 대조와 최신성 등 정해진 검사에만 해당한다.
2. 하루 한 번 USDD TRON 일별 이력과 가능한 범위의 TronGrid 확정 이벤트를 별도 릴리스로 보존한다. 실관측 행마다 `event_time`과 처음 내려받은 시각을 구분한다. 과거 일별 값은 백필이므로 당시 모델이 보았던 값이라고 주장하지 않는다. 원천의 수정이 감지되면 관측 원장에 기록하고 이미 성숙한 값의 수정은 이후 실행에서도 학습을 막는다.
3. 48시간이 지나지 않은 공급자 일별 점은 이번 연구 학습에서 제외한다. 이는 자체 보수적 기준이며 체인 최종성이나 공급자 정정 종료의 증거가 아니다. 새 성숙 일자가 생기면 **이전 체크포인트를 먼저** 새 날짜에 평가하고, 이후 시계열 가지의 새 후보를 학습한다. 매일 같은 백필을 반복 학습하지 않는다.
4. 기준선은 직전 값을 그대로 예측하는 방식이다. 후보의 시계열 오차·전진 평가를 따로 남긴다. 계획·근거·유보 헤드는 이 관측으로 학습하거나 자동 승격하지 않는다. 현재 실배분 사람 검토 정답은 **0건**이고 최신 후보는 기준선보다 나빠 `REJECTED_BASELINE`이다. `model_promoted`는 항상 `false`다.

관련 코드: [`collect.py`](../src/finagent/collect.py), [`normalize.py`](../src/finagent/normalize.py), [`quality.py`](../src/finagent/quality.py), [`real_tron.py`](fdc/real_tron.py), [`continual.py`](fdc/continual.py), [`train_real_temporal.py`](fdc/train_real_temporal.py). Cherry의 `gwdc-finance-collector.service`와 `gwdc-finance-learning.timer`가 주기를 관리하고 `data/learning/latest_attempt.json`에 마지막 시도 결과를 기록한다.

## 학습과 배포를 분리하는 승격 조건

- **입력부:** 금액과 토큰 단위, 기준 시각, 즉시 필요 금액과 최종 출금일을 독립 필드로 검증한다. 수치 계산은 정확한 Decimal과 계약 코드가 담당하고 언어 모델의 추정값을 쓰지 않는다.
- **공동 판단부:** 상품·토큰·프로토콜·담보·체인의 공유 노출과 각 근거의 시점을 연결한다. 현재 실측 시장·볼트 데이터는 수집·품질 검증 단계이며, 실제 배분 모델에 연결된 것으로 보고하지 않는다.
- **계획 출력부:** 여러 안, 비용·위험 근거, 부족한 정보, 유보 이유를 함께 다룬다. 출금 약관이나 순비용의 증거가 없으면 구매 가능하다는 결론을 내지 않는다.
- **조건 변경 학습:** 한 조건만 바꾼 가족을 통째로 같은 데이터 분할에 두고, 예산 보존·출금·공유 위험·유보 전환을 평가한다. 합성 규칙에서의 성공은 실전 성능으로 승격하지 않는다.
- **후보 평가:** 원문·권한·시점 검사 통과, 중복 및 미래 정보 누출 차단, 독립 검토 정답, 봉인된 가족별 평가, 기준선 및 이전 모델과의 전진 비교가 필요하다. 민감한 금액·출금 실패에서는 평균 점수보다 개별 치명 오류를 먼저 본다. 기준을 통과해도 제품 배포는 별도 검토다.

현재의 주기 학습은 **시계열 표현의 연구 후보 생성**이다. 소비자에게 금융 판단을 자동 제공하는 학습 루프는 사람 검토 정답·상품 약관·권한·전진 평가가 채워질 때까지 열지 않는다. 특히 9/24의 백필 일별 364개를 매일 반복해도 독립적인 새 데이터가 생기지 않는다. 앞으로 들어오는 각 날짜의 동결 체크포인트 점수와 공급자 수정 이력이 실제 개선 판단의 근거가 된다.

## 운영 중 확인할 상태

Cherry에서 `data/learning/latest_attempt.json`의 `status`, `source_errors`, `model_promoted`와 `data/learning/observation_index.sqlite3`의 수정 기록을 본다. `RUN_FAILED`, `BLOCKED_MATURE_SOURCE_REVISION`, 오래된 원천, TronGrid `RATE_LIMITED_429`는 정상 완료로 표시하지 않는다. 공개 TronGrid의 무키 요청은 429를 실제로 경험했다. 제공된 API 키 또는 전용 RPC 권한이 확인되기 전에는 이벤트 최신성과 완전성을 주장하지 않는다. 제품 판단에는 다른 근거도 확인해야 한다.
