# 자동 검증·예외 검토 운영 계약

2026-09-24. 데이터셋과 배분 오라클을 늘릴 때 사용자나 소유자가 사례를 일일이 검토하지 않도록 하는 운영 규칙이다. 이 문서는 목표 운영 계약이며, 현재 오라클의 실제 자료 학습 게이트를 해제하지 않는다.

| 단계 | 기계가 수행할 일 | 출력·다음 경로 |
|---|---|---|
| 원천 수집 | 원문, 출처, 수집 완료 시각, 대상 계약·상품, 단위, 원문 해시, 필드 위치, 사용 권한을 기록하고 재대조 | 근거가 없거나 권한이 불명확하면 학습 제외·자료 확보 대기 |
| 제약 판정 | 정수·Decimal 계산, 예산 보존, 즉시 보유액, 위험 한도, 출금 일정, 시장 상태, 근거·시점 일치와 조건 변경 검증 | 증명된 위반은 그 제약의 자동 라벨, 미증명은 `NEEDS_EVIDENCE` |
| 계획 비교 | 각 후보의 제약 통과 여부와 근거 충실도를 비교 | 모두 통과해도 어느 안이 최선인지 자동 정답으로 선언하지 않음 |
| 독립 감사 | 자동 통과·거부 양쪽에서 무작위 표본과 새로운 상품·급격한 값 변화·경계 조건을 표본 추출 | 오라클 오류율·유형과 규칙 버전별 회귀를 기록; 오류가 발견된 가족과 유사 사례를 재검사 |
| 예외 검토 | 원문 충돌, 해석이 필요한 약관, 규칙 공백, 사용자 조건의 모호함, 실제 배분의 주관적 우열만 해당 분야 검토자에게 전달 | 근거를 붙여 판정하거나 유보; 소유자의 건별 검토를 요구하지 않음 |
| 사용자 확인 | 사용자의 금액·시점·출금·위험 조건이 모호하면 해당 질문만 제시 | 조건 확정은 데이터 검토가 아니며, 실제 구매 승인은 별도 단계 |

라벨을 `source_fact_verified`, `constraint_proven`, `human_adjudicated`, `outcome_observed`, `unresolved`처럼 **증명 범위별로 분리**해 집계한다. 앞의 네 범주도 서로 다른 질문에 답한다. 원문 사실 확인이나 제약 통과는 소비자 적합성·미래 수익·구매 허가를 증명하지 않는다. 실제 결과는 체결·잔고·출금 영수증과 사후 시점이 있을 때만 관측 결과로 기록한다. 모델 자신의 제안이나 오라클의 통과 점수를 실제 최적 배분의 정답으로 되먹이지 않는다.

운영 화면에서 소유자에게 필요한 것은 수집량, 증명된 제약 라벨 수, 근거 누락·권한 미확인 수, 독립 감사 오류, 새 규칙 검토 요청, 실행 직전 승인 요청의 집계다. 자동 판정 비율을 높이기 위해 `unknown`을 임의 값이나 사람 추측으로 메우지 않는다. 현재 실제 TRON 시험 사례는 출금·비용·권한·사용자 조건 근거가 부족해 `NEEDS_EVIDENCE`와 학습 제외 상태다. 이를 풀려면 해당 근거를 확보해야 하며 소유자가 사례를 읽는 것만으로 해결되지 않는다.
